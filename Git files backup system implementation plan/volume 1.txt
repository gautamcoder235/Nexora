Nexora Memory Core Architecture Specification
Volume 1 — Core Architecture & Memory Engine

Version: 1.0 (Foundation)

1. Vision
Objective

Create a production-grade, AI-native, offline version control and memory engine for Nexora.

The system must provide the reliability and storage efficiency of Git while exposing a modern experience designed for AI-assisted development.

The user should never need to know Git exists.

Instead, Nexora should present:

Project Timeline
Smart Checkpoints
AI Change Review
Time Travel
Safe Rollback
Recovery
Session History

as first-class features.

21. Strict Engineering Rules

These rules are mandatory.

Rule 1

Never manipulate Git directly outside GitProvider.

Rule 2

Never rewrite Git history.

Rule 3

Never depend on user-installed Git.

Rule 4

Never create commits for every filesystem event.

Rule 5

Never block the UI thread.

Rule 6

Never duplicate project contents.

Rule 7

Never modify existing .git repositories.

Rule 8

Never identify projects by filesystem path.

Always use Project UUID.

Rule 9

Git stores data.

SQLite stores metadata.

Never mix responsibilities.

Rule 10

Every destructive operation must create a checkpoint before execution.

Rule 11

Every AI operation must be reversible.

Rule 12

Every snapshot must be deterministic.

The same project state must always produce the same Git state.

Rule 13

All long-running work must execute on background workers.

Rule 14

The Timeline is the source of truth for the UI.

Git history is an implementation detail.

Rule 15

Design every subsystem for future replacement.

GitProvider, EventEngine, TimelineStore, and SnapshotEngine should all have clear interfaces so they can evolve independently.

22. Success Criteria

Volume 1 is complete when Nexora has:

A bundled Portable Git that works without user installation.
A private repository under .nexora/repo.
A UUID-based project identity.
An event-driven snapshot engine with batching and debouncing.
A clear separation between Git (storage), SQLite (metadata), and the Memory Manager (orchestration).
Asynchronous processing that never blocks the UI.
A clean, extensible architecture ready for the review system and recovery features introduced in Volume 2.

This foundation should remain stable even as Nexora grows with new AI agents, plugins, and collaboration features. It establishes the core principles that every future subsystem must follow.
