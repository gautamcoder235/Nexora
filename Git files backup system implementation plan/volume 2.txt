Nexora Memory Core Architecture Specification
Volume 2 — Timeline, Review System & Recovery Vault

Version: 1.0 (Intelligence Layer)

1. Vision

The purpose of this volume is to transform Git's low-level history into a human-friendly, AI-aware memory system.

Users should never think:

"Which commit do I need?"

Instead they should think:

"Take me back to before the AI refactored authentication."

The timeline is therefore event-driven, not commit-driven.

25. Retention Policy

Automatic cleanup should preserve useful history.

Example strategy

Keep all snapshots for the last 7 days.
Keep one snapshot per day for the last month.
Keep one snapshot per week for older history.
Never remove manually created checkpoints unless the user explicitly deletes them.

Cleanup should be configurable and always preserve repository consistency.

29. Strict Engineering Rules
Rule 1

Timeline is built from Events.

Never expose raw Git commits directly in the UI.

Rule 2

Never rewrite Git history.

All restores and reverts create new commits.

Rule 3

Every AI operation must begin with a checkpoint unless explicitly disabled by the user.

Rule 4

Never restore data without passing integrity verification.

Rule 5

Never overwrite Recovery Vault generations.

Always create a new generation before pruning old ones.

Rule 6

Recovery operations must be transactional.

Either restore completely or leave the existing state untouched.

Rule 7

Do not block the UI during backup, restore, verification, or diff generation.

Rule 8

If a project path is missing, verify relocation before assuming deletion.

Rule 9

Use Git for project contents.

Use SQLite for metadata.

Do not duplicate responsibilities.

Rule 10

All restore actions must be previewable before execution.

Rule 11

Every operation affecting user data must be fully reversible.

Rule 12

Background verification must never modify repositories.

Verification is read-only.

Rule 13

The Recovery Vault must remain independent of the active project directory.

Deleting the project must never delete the vault.

Rule 14

If integrity verification fails, automatically fall back to the most recent healthy recovery generation and clearly notify the user which generation was restored.

30. Success Criteria

Volume 2 is complete when Nexora provides:

An event-driven timeline instead of a commit list.
AI sessions grouped into meaningful review items.
Smart snapshot and checkpoint policies.
Rich diff viewing with room for future hunk- and symbol-level review.
Safe restore workflows that never rewrite history.
A Recovery Vault with incremental synchronization, multiple generations, and integrity verification.
Searchable, filterable history that remains intuitive even for very large projects.

At this point, Nexora's memory system should feel less like a version control tool and more like a project time machine, where users can understand, review, and safely reverse changes without needing to think in terms of Git internals.
